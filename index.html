Bitcoin addresses and extended public keys (xpubs) cannot spend funds, but they reveal balances, transaction history, and wallet structure. Treat every generated text file as private. Do not publish it, paste it into social media, or attach it to email.

A BIP39 recovery phrase is different: it is secret and can spend funds. This page never stores or transmits anything, but only use a recovery phrase on a trusted, offline computer.

Field notes

How this works — and how to stay private.

What can I load?

Paste an account xpub for single-signature wallets. For multisig, load each cosigner xpub. A plain text file with one xpub per line works, and a BIP39 backup file with a recovery phrase can be loaded for single-signature derivation. JSON configuration files are also supported.

Use xpubs exported at the level your wallet expects. Standard single-signature account xpubs are depth 3 (for example m/84'/0'/0'). Standard multisig xpubs are usually depth 4 (for example m/48'/0'/0'/2').

Why does my xpub depth matter?

This page knows the path template but not the path that produced your xpub. It assumes the xpub corresponds to the first components of the template. Components already inside the xpub are skipped; the remaining components are derived from it. Hardened components cannot be derived from an xpub.

How private is the output?

Addresses and xpubs are sensitive but not secret: they cannot move funds, but they can reveal balances, history, and links between addresses. Keep exported files private. If you loaded a recovery phrase, that phrase is secret — clear the page and use a trusted offline machine.

Can I verify the result?

Yes. A good habit is to compare the first address with your wallet's receive screen before printing a large batch. The page implements BIP32, BIP39, BIP44/49/84/86, BIP48, BIP67, Base58Check, Bech32, and Bech32m derivation locally.
